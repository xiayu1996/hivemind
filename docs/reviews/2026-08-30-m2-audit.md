# M2 self-hosting audit, 2026-08-30

Three independent reviews were run over everything committed on 2026-08-30: the
M2 stories the pipeline developed for itself (PR #3..#8), the hand-written
hardening fixes landed on `main` while it ran, and the M1 production wiring that
merged the same morning (PR #1). This is what they found and what was done about
it. Every defect below was reproduced by a failing test before it was fixed.

## Fixed in this pass

| Defect | Where it bit | Fix |
|---|---|---|
| VERIFY pass evidence was forgeable | The runner-native fallback counted any output line naming a scenario id beside the word `passed`, so a read-only `grep` over the repository minted a green trace and `validateVerdict` accepted a self-reported pass. `passed` was also tested before `failed`, and vitest's `×` glyph was not in the failed set, so a red line could read green | Only a standalone runner marker counts, failure is read first, output from a failed tool call is skipped, and observed failures join the failed set that feeds the convergence criterion |
| The pipeline could not produce a merge request at all | S-M2-06 made Story delivery push the branch and return `mrUrl: null`, deferring to an Epic MR builder that has no production caller | Delivery opens the Story merge request whenever the Story belongs to no Epic — the degenerate story-to-main path 03 §3 mandates. `createStory` now persists the Epic membership that decides it |
| DESIGN re-entry was an unrecoverable dead end | A Story that froze its DoD then died before the transition re-froze it on re-entry, took the rejection for bad content, invalidated the completed run, deleted its artifacts and burned a fresh DESIGN session to hit the same wall — until it parked with no `dod` artifact left for a human resume | The frozen setpoint wins over anything a re-entered DESIGN produces |
| Prompt bytes were not reproducible | `previousRejections` was the one collection rendered in raw database order, ordered by two wall-clock columns that tie whenever a batch writes several rows in the same millisecond | Sorted by a stable key, tie broken on `run_id`, and filtered to the phase whose header the prompt claims |
| A rejected phase start destroyed the attempt it refused to supersede | `beginPhase` deleted unconditionally and guarded only the insert | The delete carries the same state guard |
| Discarding a completed phase result left no trace | `invalidateCompletedPhase` was the only mutation in the store with no `event_log` row | It records `phase.invalidated` |
| A card failing before it left QUEUED re-dispatched forever | The re-entry budget only counted states past QUEUED, so a startup failure spawned a full attempt every cycle | The budget covers QUEUED and reads `retry.maxPhaseReentries` instead of a hardcoded literal |
| A draft JSON payload could be adopted as the model's answer | Payload extraction merged everything between the first and last brace into one span, so a response that showed a tentative verdict and then gave its real one offered only the tentative one | Balanced object spans are collected separately; the completion judge lets any payload that withholds `done` win, and the blind verifier takes the verdict the session ended on |
| Nested acceptance criteria flattened to `[object Object]` | Which still satisfies the schema's non-empty string rule and froze as the Story's acceptance text | Flattening descends through objects and arrays |
| The scheduler reported a deadlock as a successful plan | A dependency naming a Story outside the input set never becomes satisfiable; those Stories were silently missing from every batch | A new `unschedulable` result names them |
| Epic MR evidence could never match | The check looked for `test(<storyId>): red`, but commits are named after scenarios and a Story id can never equal a scenario id | Evidence is every scenario pair beneath the Story's id |
| A crashed VERIFY session logged as a clean completion | The port hardcoded `settled: true, failure: null` while the executor swallowed the error | The runner failure reaches telemetry |

## Not fixed — ranked backlog

1. **The PLAN_APPROVAL gate delivers nothing to a human.** `present_epic_plan`
   and `create_story_page` have no outbox handler, so `story-property-delivery`
   throws, the row stays `pending`, and the orchestrator retries it forever.
   The `>8 Story` split notice rides the same operation.
2. **Nothing produces a decomposition.** No caller reaches
   `PlanApprovalStore.present()`, so no Epic can enter PLAN_APPROVAL and
   M2-01/02/03/05 cannot run end to end.
3. **The footprint scheduler is not wired into dispatch.** The live dispatcher
   still selects one card by `priority, created_at LIMIT 1`;
   `predicted_footprint` is written and read by nothing.
4. **Merge conflicts are detected but never resolved.** `EpicMergeFlow` returns
   `{kind:"conflict"}`, calls no one, and leaves the Story worktree mid-rebase
   with no `rebase --abort`. `recordMergeConflict` has no caller.
5. **`SubsetVerifier` has no implementation.** Nothing turns a scenario-id set
   into a verification run, so M2-05's subset re-verification is a type only.
6. **`EpicBranchFreshness.tick()` is never scheduled**, `schedule.epicBranchFreshnessMs`
   has no reader, and the refresh merges a local `main` with no `git fetch`.
7. **Credentials reach the agent's environment.** The runner spawns pi with the
   full parent environment, and both the orchestrator entry point and the alert
   config accept credentials from env. The secrets file should be the only route.
8. **The out-of-band alert channel is optional at startup.** With no channel a
   `NEEDS_INPUT` produces no notification and P0 becomes `console.error`, which
   is exactly the case the channel exists for. The M1-35 acceptance text was
   edited to describe this degradation rather than the requirement.
9. **The cost ledger undercounts.** The completion judge runs its own session
   per phase with no telemetry, and a phase that burns tokens and then fails the
   judge records nothing. The M1 acceptance figure is a floor, and the check
   against the Notion property is circular — that property is `SUM(cost_usd)`.
10. **Bootstrap and seed are not idempotent or target-guarded.** `databases.create`
    runs unconditionally; the stories seeder verifies no data-source title and no
    bot identity before creating 50 pages.
11. **Scenario markers are missing** from `decompose`, `scheduler`,
    `repository-scheduler`, `merge-flow` and `integration-dispatch` tests, so
    those scenarios are invisible to the L3 coverage scan and to M2-08's
    registry.
12. **The business-language lint bounces legitimate Specs** — `code`, `class`
    and `实现` are blacklisted, which kills "promotion code" and "实现客户自助退款".
