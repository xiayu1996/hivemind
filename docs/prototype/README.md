# Hivemind 管理后台界面契约

从 `index.html` 开始按主要流程浏览。`pages/` 中每个文件对应一张页面卡；页面的 `<title>` 与说明文字定义页面名称和用途。

## 消费方式

- 实现页面时，以 `design.md` 解释的层级和行为为准，以 `components.md` 约束组件用途与状态。
- 视觉值只能取自 `tokens.json`；`shared.css` 是这些值在原型中的对应表达。
- 每个业务页面默认展示正常状态，并可追加 `?state=empty`、`?state=loading`、`?state=error` 或 `?state=waiting` 查看完整状态页。
- 桌面和手机使用同一页面；手机宽度下不得删除桌面端可执行的操作。

## 修改规矩

- 新增页面可以复用现有 token 和组件规则，不得为单页另造同义颜色或状态。
- 修改既有 token、视觉方向或页面范围前，需要先取得仓库级批准。
- 当前设备不在家庭或办公网络时，只能展示访问受限状态，不得展示任何后台内容。
- 待办动作只有在 Notion 确认保存后才能显示为已处理。
- 费用历史展示发生时固化的价格和美元金额，不按之后的新价格重算。
- 角色配置保存或恢复时，必须明确只影响之后新开始的智能体。
- HTML 中只放使用者需要看到和操作的内容，不放设计理由或验收声明。
