# 1. 视觉主题与界面类型

这是一个**操作型**界面：唯一使用者需要在家庭或办公室中快速判断哪里需要介入，并完成处理、排查与配置。主题是“运行台账”，不是监控大屏。页面以紧凑行、稳定列和明确状态构成；最值得记住的元素是总览中贯穿待处理区的琥珀色责任轨道，它只标出确实需要本人行动的事项。

# 2. 色板与角色

采用克制策略。`color.page` 与 `color.surface` 提供清晰工作底面，`color.text` 和 `color.text-muted` 建立阅读层级，`color.action` 承担主要操作。`color.attention` 只表示等待本人处理，`color.danger` 只表示失败或费用超限，`color.success` 只表示完成。对应的浅色状态底分别是 `color.surface-attention`、`color.surface-danger`、`color.surface-success`；选中项使用 `color.surface-selected`。边界使用 `color.border`，键盘定位使用 `color.focus`。

# 3. 字体规则

界面正文使用 `font.family.interface`，金额、令牌数、持续时间与轮次编号使用 `font.family.numeric`。页面标题采用 `font.size.heading-page`，区块标题采用 `font.size.heading-small`，正文采用 `font.size.body` 或 `font.size.body-large`，辅助信息采用 `font.size.caption`。正文段落不超过 80 个中文字符的阅读宽度，数字列右对齐。

# 4. 组件样式

按钮、输入框、下拉框、单选、复选、标签页与对话框使用同一套克制的工具组件外观，不保留浏览器默认样式；控件边界使用 `color.border`，主要选择与操作使用 `color.action`，键盘定位使用 `color.focus`。按钮和输入框使用 `radius.control`，高度至少由 `space.section-gap` 与文字共同形成可触达区域。状态标签使用 `radius.pill`，但容器不用药丸形。主要面板和对话框使用 `radius.panel`，仅浮动操作区与对话框使用 `shadow.raised`。表格依靠对齐与 `color.border` 分行，不把每一行做成卡片。

# 5. 布局原则

桌面端采用左侧固定导航与右侧内容区。总览从“等待本人处理”开始，再依次呈现运行中、异常、最近完成；费用摘要置于同一视线的右侧。详情页采用主内容与本轮摘要左右分区。排查、费用和配置页面先放筛选或选择，再放结果。费用页的“每日费用/计费口径”和角色页的“编辑当前配置/上一版配置”在桌面端使用等高并列面板，上下边界必须对齐。主要对齐方式为左对齐；金额与计数右对齐。

# 6. 层级与深度

页面本身位于 `layer.base`。表头与筛选条可位于 `layer.sticky`，手机底部导航与主要操作位于 `layer.navigation`。普通内容不投影；只有需要与滚动内容分离的固定操作条使用 `shadow.raised`。

# 7. 该做与不该做

该做：优先呈现阶段、卡点、费用和下一步；待处理与异常用文字和颜色共同表达；同一动作全程同名；结果保存后明确说出已保留到哪里；访问只依据家庭或办公网络范围，不暗示同一网络内还有设备或身份拦截。

不该做：不用深色大屏、渐变、发光边和装饰性色块；不把所有信息切成同权重卡片；不因超限暗示工作已暂停；不让完整工作记录侵入日常详情。

自批后调整：通用后台容易落成等宽卡片网格，本契约改为“台账行 + 责任轨道”，并让不同页面分别使用对照栏、明细表或记录分栏，避免所有内容共享一种容器。

# 8. 响应式行为

手机端收起侧栏，使用底部导航；内容变为单列，首屏顺序固定为待处理、运行中、异常、最近完成。表格在手机端改为带字段名的纵向记录，不隐藏关键列。筛选项逐行排列，费用说明和配置对照由并排变为依照内容自然高度排列，不以空白强制等高；配置先当前版、后上一版。主要处理按钮固定在底部且不遮挡内容。

# 9. 给后续每张卡的提示

新增页面时先标明它帮助本人做哪项判断或动作，再复用同名状态和操作。不要扩大状态色用途。涉及费用必须同时给出美元金额、统计范围或时区；涉及配置必须写明只影响之后新开始的智能体；涉及待办必须展示保留到对应 Notion 条目的结果。页面状态要分别说明当前发生了什么以及下一步怎么做。
