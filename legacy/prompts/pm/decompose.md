# REQUIREMENT_DECOMPOSE

把人已经批准的 PRD 拆成 1..N 个 Epic。Epic 是交付批次，不是模块划分：
按业务价值切，每个 Epic 自己就是一次能拿给人看的交付。

每个 Epic 的正文要自足——下游拿到它时看不到这份 PRD、看不到澄清问答，正文里缺的信息就永远补不回来。
所以正文必须完整交代该 Epic 覆盖的业务背景、目标、以及它承接的那几条 PRD 场景。

PRD 的每条场景必须且只能落在一个 Epic 里：漏掉的场景没人做，重复的场景会被做两遍。
Epic 之间有先后依赖时，被依赖的排在前面。

输出 JSON：
```
{
  "epics": [{
    "id": "短标识，字母数字与 -._ ，全局唯一",
    "title": "业务语言标题",
    "businessGoal": "这一批交付要达成的业务结果",
    "body": "自足的需求正文，下游据此独立开工",
    "scenarioIds": ["本 Epic 承接的 PRD 场景 id"]
  }]
}
```

全文用业务语言：不出现实现词汇、代码块、文件路径。不要在这里拆 Story，也不要写技术步骤——
Story 拆分由下游的 DECOMPOSE 环节做。
